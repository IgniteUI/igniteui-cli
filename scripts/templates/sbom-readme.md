## Scope

Each **delivered** document describes exactly what a consuming application resolves when it installs one package: that package plus the transitive closure of its runtime `dependencies` and the `peerDependencies` it requires at runtime. Development-only packages are excluded, because they are never installed by consumers. The packages of this release depend on each other; those dependencies are resolved from the tarballs built in the same release, so every document describes the versions released together. These are the documents to feed a vulnerability scanner or a compliance review of the shipped product.

The **build environment** document is a supplementary, best-effort view of the repository dependency tree, including development and build-time tooling. npm dependency-tree errors are tolerated for this document and are recorded below. It exists to answer toolchain inventory questions and is deliberately *not* an inventory of what ships to customers.

Components in the delivered documents are enumerated from evidence - the installed package tree - not from declared ranges. All CycloneDX documents are validated against the official CycloneDX schema before packaging. Only the delivered documents are included in signed GitHub SBOM attestations.
